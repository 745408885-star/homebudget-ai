# Legacy V1 冻结政策

生效版本：`v0.1.0-alpha.1`

## 1. 冻结范围

Legacy V1 包括：

- `/legacy` 下的旧首页、三步问卷和最终估价页面；
- `frontend/src/pages`、`frontend/src/hooks/useBudgetPlanner.ts` 及其 V1
  公共组件；
- `POST /api/budget/calculate` 和现有 V1 分类、项目 API；
- `backend/app/services/budget_engine.py` 及评分、分配、报告模块；
- 当前 V1 ORM、仓储、正式 Alembic 迁移和历史数据。

`backend/app/services/budget_engine_v2.py` 是未接入的 V2 设计接口，不属于
Legacy V1 的运行时实现。

## 2. 允许修改

冻结后仅允许：

- P0 安全修复；
- 无法启动或核心流程完全不可用的阻断修复；
- 严重兼容性修复；
- 为迁移到 V2 所必需、范围最小且有回归测试的调整；
- 回滚、历史结果读取和 V1/V2 对照测试所需维护。

## 3. 禁止修改

冻结后禁止：

- 新功能、新问卷字段或新数据接口；
- 新预算规则、新商品模块或新推荐能力；
- UI 改版和交互扩展；
- Budget Engine V1 算法优化或产品规则调整；
- 与 V2 竞争研发资源的独立演进。

## 4. 保留原因

Legacy V1 用于历史方案兼容、回滚、结果对照以及验证 V2 迁移前后的行为。
现有代码、数据库结构、正式迁移和历史快照不得因冻结而删除或重写。

## 5. 当前产品主线

V2 是唯一产品主线，默认入口为 `/`。当前 V2 仍是 Alpha 交互原型，
Budget Engine V2 尚未正式接入，金额属于原型估算或实验数据，不是最终
商品或工程报价。

Legacy V1 仅通过 `/legacy` 访问，不再作为默认入口。

## 6. 未来删除条件

删除 Legacy V1 前必须同时满足：

1. V2 正式引擎、API 和持久化方案完成并通过发布评审；
2. 历史 V1 方案有经过验证的只读访问或迁移路径；
3. V1/V2 对照测试达到产品所有者批准的结果；
4. 回滚方案、数据保留期限和用户告知方案获得批准；
5. 生产监控确认不存在仍依赖 V1 的关键流量；
6. 产品所有者明确批准删除范围和发布版本。

## 7. Legacy Issue 提交

Legacy 问题应使用 Bug 模板，并在标题前加 `[Legacy V1]`。Issue 必须说明：

- 是否属于安全、启动阻断或严重兼容问题；
- 复现路径、环境和预期/实际结果；
- 是否影响历史结果读取或 V2 迁移；
- 为什么修复符合本冻结政策。

普通功能请求、UI 改版或算法优化应关闭或转入 V2 产品规划。
